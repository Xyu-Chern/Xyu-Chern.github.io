On feedback, timing, and robot execution

The Space to React

A robot can see what changed—and still have no time left to change what it does.

Xu Chen · November 2026 · Simulation study

Imagine a robot moving toward one of two targets. An image will tell it which target is correct. Until that image arrives, both possibilities remain open. The robot can plan ahead, but some of those commands may already be on their way to the motors.

The interesting question is not just whether the robot receives the right information. It is whether that information can still change the actions that matter. This note explores that gap using a small, controlled robot simulation.

A deliberately small experiment

A simulated Franka arm executes a left-or-right reaching task in PyBullet. The controller receives a rendered marker image after a controlled delay. It chooses discrete commands, which pass through a first-in, first-out queue before affecting the arm.

There are 12 command slots. We vary when the image arrives, how long commands wait in the queue, and how many commands the controller commits to before planning again. All methods share the same image decoder, inverse kinematics, motor controller, action set, and finite solver.

What exactly was evaluated?

The frozen formal evaluation contains 390 nominal timing trials (78 configurations × 5 rules) and 960 perturbation trials. Another 120 serial repeats measure controller time. Two separate post-hoc diagnostic studies contain 240 trials each. These groups answer different questions and are not pooled into a single success rate.

The task uses exact proprioception and a simple marker decoder. It is noncontact reaching in simulation, not a learned visual policy or a real-hardware insertion result. Computation advances the execution clock; queued commands can execute while the controller computes. Rendering and physics integration are environment-generation costs, excluded from controller timing.

1. The picture is not the whole state

Two robots can occupy the same physical state while having different futures already committed. One queue may hold the arm still. Another may continue pushing it forward. The same correction can work for one and fail for the other.

In a separate matched-state contact-simulation diagnostic, we tested 13 candidate waits while fixing the recorded physical state and queue length. Across 32 states, six hold-versus-advance pairs had nonempty but disjoint successful wait sets. Reversing the order of the same command multiset produced one such pair.

To decide what can still be done, the controller needs to know what it has already committed to doing.

This is a distinction within the tested candidate family, not a proof that all possible continuous controllers require different actions. It motivates including pending commands and their order in the execution state.

2. When does feedback stop being useful?

Our finite model places command issuance, immutable commitments, observation delivery, and computation on one clock. A commitment is accepted only when it remains safe in every retained environment and every possible delivered observation still leaves a successful continuation.

An exact information-set recursion checks those branches. Decision-preserving signatures allow equivalent continuation problems to be reused without changing their winning commands. This specializes established partial-observation planning ideas to an explicit execution interface.

3. Fewer calls do not mean less computation

Short commitments preserve opportunities to react. Adaptive commitments can keep those opportunities while calling the planner less often. But a reusable policy can encode the observation branches in advance, so repeated planning is not the only way to remain responsive.

The evidence supports a timing boundary and its execution—not a success or computational advantage over compiled reuse.

4. A feasible plan can still fail on the robot

In the perturbation sweep, adaptive execution succeeds in 24/24 nominal-geometry cases. Faster execution and lower servo gain each fail in 24/24 cases despite model-certified prefixes. A discrete model of intended motion does not automatically cover the robot’s response.

Failure also does not identify its own cause. The original solver prefers less motion among feasible solutions and can postpone progress. In a separate post-hoc intervention, prioritizing progress after observation recovers 16/24 fast executions, for every tested rule. It recovers none of the low-gain cases.

A missed target may reflect late information, delayed actuation, a poor choice among feasible plans, or an inaccurate response model. Those explanations need different tests.
What does the guarantee cover?

The recursion certifies feasibility within its retained transitions and information model. Independent enumeration agrees on 282 abstract cases, and all 1,350 formal records pass the execution-clock and observation-causality checks. Those checks do not establish model coverage of arbitrary robot physics.

The low-gain intervention does not fully separate tracking limitations from the remaining correction window. The original delayed contact-insertion task remains unresolved. Neither the nominal results nor zero contact violations in a noncontact task establish general physical safety.

What this study contributes

  1. An explicit execution contract. Pending commands, irreversible commitments, delayed observations, and computation become part of the feasibility question.
  2. An exact finite solver with reusable decisions. Observation branches retain successful continuations, with reuse that preserves the set of winning commands.
  3. A diagnostic evaluation. Controlled robot simulations connect the predicted feedback deadline to executed behavior, compare replanning with compiled reuse, and expose where model feasibility stops predicting physical success.

The next step is to include validated response uncertainty and execution margins, then test whether online replanning provides benefits beyond a reusable branch policy. The useful outcome here is a sharper question: at this moment, with these commands already committed, which corrections are still executable?
